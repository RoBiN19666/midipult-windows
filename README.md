Windows-оболочка вокруг веб-панели **[MidiPult](https://github.com/RoBiN19666/midipult)** для
рутованной **Яндекс Станции Миди**. Приложение не содержит интерфейс панели: оно находит
колонку в локальной сети и открывает её панель во встроенном WebView2. Изменения панели
**не требуют пересборки клиента**.

Текущая версия — **1.0.1**.

Клиенты для панели:

- [MidiPult Android](https://github.com/RoBiN19666/midipult-android) — версия для телефона:
  поиск станций, карточки, меню и системный медиаплеер.

## Возможности

- автоматический поиск колонок по UDP (порт `8056`) и ручное добавление по адресу;
- несколько колонок: выбор, переименование, удаление, отметка активной;
- **одно окно на всё приложение**: панель открывается прямо в списке, вернуться можно
  кнопкой «←» — второе окно больше не появляется;
- панель управления на странице колонки — узкий ползунок у левого края: при наведении
  раскрывается в кнопки «список», «обновить», «открыть в браузере», «на весь экран»;
- ползунок не перекрывает шапку и логотип панели колонки даже на узком окне;
- тёмный заголовок окна и никакого нативного меню — оформление не зависит от темы Windows;
- проверка доступности панели до открытия и понятное сообщение об ошибке вместо
  пустого экрана, с кнопкой «Повторить»;
- **обновление по кнопке** из GitHub Releases: обязательная проверка SHA-256, установка
  поверх с сохранением настроек, автоматический перезапуск;
- сохранение списка между запусками;
- PIN-вход панели и cookies работают как в обычном браузере — сессия не теряется
  при перезапуске;
- портативный режим (`--portable`) — настройки лежат рядом с exe;
- установка **без прав администратора** и запроса UAC;
- один файл `MidiPult-<версия>-portable.exe`, без установки и зависимостей, кроме WebView2;
- обновления панели и приложения — независимые каналы.

## Требования

- **Windows 10 / 11 x64**;
- **Microsoft Edge WebView2 Runtime** — в Windows 11 уже установлен, в Windows 10 может
  потребоваться [Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/);
- компьютер и колонка в одной локальной сети;
- на колонке установлена и запущена панель **MidiPult** на порту **8055**;
- UDP-порт **8056** не заблокирован роутером (иначе — добавление по адресу).

## Установка

Скачайте `MidiPult-<версия>-setup.exe` из [релизов](https://github.com/RoBiN19666/midipult-windows/releases)
и запустите его.

- установка **пользовательская** — права администратора не нужны, запрос UAC не появляется;
- программа кладётся в `%LOCALAPPDATA%\Programs\MidiPult`, настройки — в `%APPDATA%\MidiPult`;
- ярлык в меню «Пуск» создаётся всегда, ярлык на рабочем столе — по отмеченному флажку;
- удаление: «Приложения и возможности» → MidiPult → Удалить (список колонок и настройки
  остаются).

Устанавливать не обязательно: `MidiPult-<версия>-portable.exe` работает так же и ничего не пишет
в реестр.

## Как подключить

1. Запустите `MidiPult-<версия>-portable.exe` (или ярлык после установки).
2. Убедитесь, что компьютер и колонка в одной Wi-Fi / LAN-сети.
3. Нажмите **«Найти колонки»** — найденные колонки добавятся в список.
4. Выберите колонку кнопкой **«Открыть»**.
5. Если поиск не работает, нажмите **«Добавить по адресу»** и введите, например
   `192.168.1.10:8055`. Схему `http://` и порт можно не указывать — подставится `8055`.
6. Переименовать или удалить колонку можно кнопками-карандашом и крестиком в её карточке.

## Горячие клавиши

Работают в списке колонок:

| Клавиши | Действие |
| --- | --- |
| `F5` / `Ctrl+R` | Найти колонки |
| `Ctrl+N` | Добавить колонку по адресу |

## Панель управления колонкой

Когда открыта панель, у левого края по центру висит узкий тёмный ползунок — шапку и логотип
панели он не перекрывает. Наведите мышь — раскроются кнопки, уведите — ползунок свернётся:

- **←** — вернуться к списку колонок (в этом же окне);
- **⟳** — обновить панель;
- **↗** — открыть панель в системном браузере (например, для скачивания резервной копии);
- **⛶** — на весь экран.

Ползунок нарисован в `shadow DOM`, поэтому не конфликтует со стилями самой панели
колонки и не мешает её кнопкам.

## Где хранятся настройки

По умолчанию:

```
%APPDATA%\MidiPult\stations.json
%APPDATA%\MidiPult\midipult.log
%APPDATA%\MidiPult\webview\      профиль WebView2 (cookies, сессия панели)
```

В портативном режиме (`MidiPult-<версия>-portable.exe --portable`) — папка `data` рядом с exe. Свой каталог
можно задать через `--data-dir <путь>` или переменную окружения `MYPULT_HOME`.
Кнопка **«Папка настроек»** в подвале открывает этот каталог.

## Обновления

Клиент проверяет обновления **по кнопке**: подвал → «Проверить обновления». Сам он ничего
не скачивает и не устанавливает — каждое обновление это явный клик.

- источник — GitHub Releases репозитория `midipult-windows`, только `https` и только хосты
  GitHub;
- версия сравнивается с `APP_VERSION`; черновики и пре-релизы пропускаются;
- **SHA-256 обязателен**: без файла `.sha256` в релизе обновление не предлагается, а при
  несовпадении хеша скачанный файл удаляется и установка отменяется;
- **установленная версия** — скачивается `MidiPult-<версия>-setup.exe` и запускается тихо
  (`/SILENT /CLOSEAPPLICATIONS`); тот же `AppId` обновляет приложение поверх, настройки в
  `%APPDATA%\MidiPult` не трогаются, права администратора не нужны;
- **портативная версия** — скачивается `MidiPult-<версия>-portable.exe`, текущий файл
  переименовывается в `.old` и заменяется (при ошибке — откат), приложение
  перезапускается, а старый файл удаляется при следующем старте;
- после установки приложение перезапускается само.

Сборка не подписана, поэтому тихих обновлений без действия пользователя здесь нет
намеренно: обновление — это клик и проверенный хеш.

Панель обновляется отдельно, из своего репозитория, и клиент при этом не пересобирается.

## Сборка

Нужен **Python 3.12+** для Windows.

```powershell
python -m pip install -r requirements-dev.txt
.\build.ps1
```

Готовые файлы: `dist\MidiPult.exe` (локальный запуск), `dist\MidiPult.exe.sha256`
и портативный для релиза — `dist\MidiPult-<версия>-portable.exe` с `.sha256`.

Для быстрого запуска без сборки:

```powershell
python app.py
```

Папка вместо одного exe (запускается быстрее):

```powershell
.\build.ps1 -OneDir
```

### Установщик

```powershell
.\build-installer.ps1
```

Готовый файл: `dist\MidiPult-<версия>-setup.exe` и `.sha256`.

Нужен **Inno Setup 7**. Если его нет, скрипт сам скачает и установит его в
`%LOCALAPPDATA%\MidiPult\tools` (без прав администратора). Свой путь к `ISCC.exe` можно
задать переменной окружения `INNOSETUP`.

Полная проверка — сборка, тихая установка, запуск приложения и удаление:

```powershell
.\build-installer.ps1 -Test
```

Версия в `app.py` и в `installer\midipult.iss` должна совпадать — скрипт проверит это и
остановится с ошибкой.

### Тесты

```powershell
python -m unittest discover -s tests -v
```

Покрыты разбор адресов, хранилище, UDP-поиск (с тестовым ответчиком), проверка доступности
панели.

## CI и релизы

Workflow `.github/workflows/windows.yml` собирает exe и установщик на `windows-latest` по
тегу `windows-v*` или вручную (`workflow_dispatch`).

- тег обязан совпадать с `APP_VERSION` в `app.py`;
- к релизу прикладываются `MidiPult-<версия>-portable.exe`, `MidiPult-<версия>-setup.exe`
  и `.sha256` для обоих файлов;
- секреты репозитория не нужны — подписи у сборки нет (см. «Ограничения»).

Релиз: обновите `APP_VERSION` в `app.py` и версию в `installer/midipult.iss`, закоммитьте,
поставьте тег `windows-vX.Y.Z` и отправьте его в GitHub — workflow соберёт и опубликует
файлы.

## Проверка сборки

Скачанный файл можно сверить с релизом, не запуская его:

```powershell
(Get-FileHash .\MidiPult-<версия>-portable.exe -Algorithm SHA256).Hash
Get-Content .\MidiPult-<версия>-portable.exe.sha256
```

Хеши должны совпасть. Сборку можно воспроизвести самостоятельно — из этих же исходников
через `.\build.ps1`; `app.py` и `core.py` в exe компилируются целиком, поэтому сравнение
поведения с исходниками возможно.

## Ограничения

- **Только Windows 10/11 x64.** Версий для macOS и Linux нет.
- **Это клиент, а не сервер.** Панель должна работать на самой колонке; без неё открывать
  нечего.
- **HTTP без TLS.** Панель намеренно не использует HTTPS (см. README панели).
- **Нет фоновой работы, трея и автозапуска** — приложение активно только когда открыто.
- **Скачивание файлов** надёжнее делать через «Открыть в браузере»: встроенный WebView2
  может не показывать диалог сохранения.
- **Голосовые команды** выполняются Алисой на колонке, а не на компьютере.
- **SmartScreen** может предупредить о неизвестном издателе: ни портативный файл, ни
  установщик не подписаны. Это ожидаемо для локальной сборки — сверяйте SHA-256.

## Безопасность

- окно одно, поэтому мост в Python технически виден и странице колонки; всё, что трогает
  файлы, настройки и поиск в сети, доступно **только локальному лаунчеру** — каждый метод
  сверяет текущий адрес страницы;
- кнопки плавающей панели вызывают только оконный хром (назад, обновить, браузер, полный
  экран) и не принимают адресов;
- «О программе» — обычный диалог внутри страницы, отдельное окно не открывается;
- PIN панели проверяется на колонке; приложение лишь хранит cookies WebView2;
- список колонок и лог лежат в профиле пользователя; секретов панели (токены, ключи)
  приложение не хранит;
- наружу приложение не ходит: только UDP-поиск в локальной сети и HTTP к выбранной колонке;
- единственное исключение — проверка обновлений, и только по кнопке: `https` + хосты GitHub,
  обязательный SHA-256, никаких тихих установок.
